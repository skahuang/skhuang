## 1. 核心概念（一句話）

**最後一個倖存者以為巨爪是救援，結果在半空中被甩落，摔回屋頂、被喪屍壓制。鏡頭一路拉遠——原來她只是夾娃娃機裡的獎品，玩家 Nova 差一點就夾到她了，然後投下下一枚硬幣。**

### 為什麼用「3D 場景 + 2D 角色」——把限制變成設定

機台裡的人物全部是**壓克力立牌**（2D 圖片 + 透明小底座）。所以：

- 前 45 秒觀眾覺得 2D 角色只是畫風；揭曉時鏡頭從側面一掃，看到他們全是**薄片立牌**，這個風格選擇本身就成了伏筆。
- 2D 角色不用做到完美的 3D 透視，GPT 生出來的圖本來就是平面的，剛好合理。
- 喪屍群可以大量複製同一張圖（96 個立牌只要 4 種 × 3 個姿勢），省掉大量算圖時間。

Nova（現實世界的玩家）同樣用 2D 立牌呈現，但畫得更細、打光更完整，跟機台內的世界做出區隔。

## 2. 故事板檢查：需要調整的地方

你現有的 8 格故事板只有 **20 秒**，要撐滿 60 秒，結構要重排。下面依重要程度排列：

### 必改（不改會影響上架表現或成片）

1. **開場太慢。** 01 格「困在屋頂」是 3 秒靜態大遠景，Shorts 有 70% 觀眾在 1.7 秒內決定要不要滑走。→ 改成**第 0 秒就是門被撞得變形的特寫**，加上倒數計時，遠景移到第 3 秒。
2. **搖桿和投幣口落在 Shorts 的介面遮擋區。** 07、08 格裡的搖桿和投幣手勢都在畫面最下面 12–15%，YouTube Shorts 底部約 300px 會被標題、按鈕蓋住。→ Nova 的鏡頭要把控制台往上構圖，主要動作放在中間 900×1400 的安全區內（腳本裡的 S15/S17a 已經這樣調整）。
3. **伏筆不夠，揭曉像是硬轉。** 現在 01–06 格沒有任何「這是機台」的暗示，觀眾會覺得被騙，而不是「原來如此」。→ 埋 4 個可以重看的線索（見第 4 節）：計時器、月亮其實是天花板燈、反光的地面、立牌底座。
4. **04 格有天空和月亮，但機台內部應該有天花板。** → 把月亮設定成**機台頂部的圓形 LED 燈**，背景天空是印在櫃體背板上的輸出圖，揭曉時一看就懂。
5. **調性：驚悚、有受傷感、不血腥；Rin 維持原本的風格。** 你上傳的 RIN 設定圖和六姿勢圖就是標準，不再修改造型。受傷用**擦傷、瘀青、髒污、紅腫抓痕、撕破的衣服**表現，**完全不出現血**。因為 Rin 是兒童外觀，這幾點要守住：
   - **紅外套的破邊要是乾的布料鬚邊**。原本設定圖的破邊有點像在往下滴，加上「不要血」的規則後，生圖時要特別寫明是布料，避免看起來像血（`ASSET_PROMPTS.md` 的風格鎖定已經寫進去）。
   - **壓制畫面只有抓、拉、壓**：外套被扯但不露出身體，觸手纏手臂和腳踝、不纏脖子；不咬、不打、不流血。
   - 上架時把觀眾設定成**「不是為兒童打造」**（有恐怖驚嚇元素）。沒有血腥的話，通常不需要自己加年齡限制，也比較有機會拿到完整的廣告收益。
6. **2D 角色改成逐幀動畫，每個鏡頭都有動作。** 每個動作是一張組圖（例如 4×2 共 8 格），Blender 自動切格，用每秒 12 或 8 張播放，效果像微縮模型的定格動畫。做法見第 5.3 節。
### 建議改（讓故事更完整）

7. **Rin 的鞋子前後不一致。** 設定圖正面兩腳都有靴子，側面一腳光腳；故事板裡又兩腳都光腳。→ 寫進劇情：**第 7 秒喪屍抓住她的腳踝，扯掉一隻靴子**。之後一腳靴子、一腳光腳。揭曉時，獎品出口裡躺著**好幾隻小靴子**（代表之前好幾局都失敗了），一個黑色幽默的呼應。
8. **比例要鎖死。** 01 格水塔大約是 Rin 身高的 3 倍，07 格夾爪的寬度約等於水塔。腳本已經固定比例：Rin 2.3 cm、水塔約 12 cm 高、夾爪張開約 16 cm、櫃內空間 90×90 cm。GPT 生圖時不用管比例，在 Blender 裡縮放即可。
9. **07 格機台裡看得到整座城市，但櫃體深度裝不下。** → 近處用 3D 方塊做大樓，遠處靠背板輸出圖 + 前高後低的強迫透視。
10. **喪屍設定要統一。** Z01 設定圖也是一腳靴子一腳光腳，觸手有的從手臂長、有的從背部長。→ 統一規則：觸手**只從肩膀和背部長出來**，每個變體保留一個辨識度高的剪影（工人連身服／觀光客襯衫／胖警察／黃雨衣）。
11. **結局要能無縫循環。** Shorts 會自動重播，重播率會算進觀看時間。→ 最後 3 秒機台重置，Rin 回到屋頂中央，抬頭看向鏡頭（看向 Nova，也就是觀眾），鏡頭甩回門的特寫，**最後一格接回第 1 格**。
12. **降雨。** 你的新圖都有大雨，氣氛很好，所以保留，並把它也變成線索：雨只在合成時疊加在**機台內的鏡頭**上；S15 鏡頭穿過玻璃的那一刻，雨**瞬間消失**，只剩玻璃內側的水珠。觀眾會回頭想：原來那場雨也是機台的特效。
13. **新畫面裡水塔還掛在夾爪上。** 這比原本「水塔整個掉下來」更好：**夾爪其實夾穩了，被甩掉的只有 Rin**。揭曉時夾爪把空水塔送進獎品出口：Nova 夾到的是錯的獎品。腳本和 Blender 動畫已經改成這樣。

### 不用改（現在就很好）

- 新的壓制畫面：四種喪屍都有出現（警察扯外套、黃雨衣伸觸手、工人抓頭、觀光客壓手臂），角色辨識度很好。第三張的 9:16 低角度特寫可以直接當 S13 的構圖。
- 01/02 的屋頂配置（樓梯間在左後方、水塔在右後方）跟屋頂參考圖一致，腳本照這個配置建模。
- 綠色門燈和遠處的橘色火光是好的冷暖對比，延用。
- Nova 的設定（紫色飛行外套、黃綠色髮夾、BORED／ALMOST／SMIRK 表情、拿硬幣的手勢）已經完整，直接用來做表情和手部特寫。
- 迷你模型的移軸淺景深剛好支撐揭曉，Blender 的鏡頭景深已經照這個方向設定。

## 3. 腳本 + 分鏡表（60 秒，18 個鏡頭）

**旁白：無。** 整支片靠音效和音樂推動，只有 Nova 在最後說一句台詞，所以不用翻譯也能跨語言傳播，也適合靜音觀看。
**畫面文字：** 只有 3 張文字卡 + 一個全程顯示的倒數計時器。

> **計時器詭計：** 畫面右上角從第 0 秒開始顯示 `00:32` 倒數，觀眾會以為是「她還能撐多久」。第 32 秒歸零的瞬間，Rin 的手剛好鬆開。揭曉時才看清楚，那是**夾娃娃機的遊戲計時器**（機台頂部的紅色 LED 顯示 `00:00`）。

## 5. Blender 製作方式

### 5.1 一鍵建場景

```bash
# 需要 Blender 4.2 以上（已在 bpy 5.0.1 實測可建檔、可算圖）
blender -b -P almost-short/blender/build_almost_scene.py -- --out almost-short/almost.blend
# 加上預覽算圖（每個鏡頭一張）
blender -b -P almost-short/blender/build_almost_scene.py -- --out almost-short/almost.blend --preview almost-short/previews/
```

或是打開 Blender → Scripting 分頁 → 開啟這個 .py → Run Script。

**腳本會建好：**

- **真實比例的櫃體**（1 × 1 × 2 m）：玻璃、霓虹燈條、招牌、控制台（搖桿、按鈕、投幣口）、紅色 LED 計時器、獎品出口和小靴子、印刷背板、當作「月亮」的天花板燈。
- **1:60 屋頂微縮模型**：主建築、女兒牆欄杆、樓梯間 + 有鉸鏈動畫的鐵門、冷氣主機、60 棟周邊大樓、會發光的火點。
- **水塔**（塔身、塔頂、4 支腳、梯子）和**三爪夾子**（每支爪有自己的旋轉軸，可以做開合動畫）。
- **2D 立牌系統**：每張角色圖都是一片有透明度的平面，腳下有小底座，而且會自動轉向目前的鏡頭（Locked Track → `FACE_TARGET`）。
- **96 個喪屍立牌**：從門口分批湧出，走到水塔周圍後原地輕微晃動；4 種變體 × 3 種姿勢共用材質。
- **完整的 60 秒動畫**：撞門、開門、夾爪下降 → 夾住 → 提起 → 抖動、Rin 從水塔摔到屋頂、三層壓制立牌、一半的喪屍圍上去、夾爪把空水塔送進獎品出口、機台重置。
- **18 台鏡頭**，全部綁在時間軸標記上，按播放或算全片時會自動切換鏡頭。微縮鏡頭用 f/2.8–f/8 的景深做出移軸感。

`previews/blockout_contact_sheet.jpg` 就是這支腳本實際算出來的 18 個鏡頭（色塊是佔位圖）。

### 5.2 放入美術素材

1. 用 `ASSET_PROMPTS.md` 生成 PNG，**檔名要完全一樣**，放到 `assets/sprites/`（角色）和 `assets/textures/`（背景）。
2. 重跑腳本，佔位色塊就會被換成你的圖，寬高比會自動讀取圖片的尺寸。
3. 想換姿勢，只要多做一個立牌物件，用 `key_visible()` 設定它在哪個鏡頭出現即可（參考 `build_characters()` 裡 Rin 的各個動作）。新增逐幀動作時，記得在腳本開頭的 `ANIM` 表加一行。

### 5.3 2D 逐幀動畫怎麼做

所有角色都是**逐幀動畫**：每個動作畫成一張組圖，Blender 用 UV 視窗一格一格往下切換，跟傳統的 sprite sheet 一樣。

| 角色 | 做法 | 速度 |
|---|---|---|
| Rin | 每個鏡頭一組動作（後退、扯靴子、爬梯、發抖、伸手、滑落、墜落、落地、掙扎、抬頭），共 9 組 70 格 | 動作戲 12fps；情緒戲（伸手、掙扎）8fps，用來回播放模擬呼吸 |
| 喪屍 | 4 種 × 3 個姿勢（走、伸手、爬），共 12 組 80 格；每組自動做 3 種時間偏移，旁邊的喪屍不會同步 | 12fps / 8fps |
| 壓制畫面 | 後層、Rin、前層各一組，8fps 來回播放的掙扎和拉扯 | 8fps |
| Nova | 搖桿、嘆氣轉頭、投幣三組，共 28 格 | 12fps / 8fps |

**運作方式（腳本已經做好）：**
- 腳本開頭的 `ANIM` 表定義每個動作的格數、速度和播放方式：`loop`（循環）、`once`（播一次後停在最後一格）、`pingpong`（來回播放）。
- 把 `<名稱>_sheet.png` 放進 `assets/sprites/`，重跑腳本就會自動切格播放。也可以先放單張的 `<名稱>.png`，會當成靜止圖使用。
- 還沒有素材時，佔位圖也是會動的組圖（身體搖晃、手臂擺動），可以先檢查節奏。
- 想調整速度或格數，直接改 `ANIM` 表的數字，不用動其他程式碼。

**為什麼用組圖，不用每格單張生成：** GPT 在同一張圖裡畫完整組動作，服裝和臉會比較一致；分開生成每一格，連起來播放會閃爍抖動。對不齊的話，先生成第一格和最後一格，再請 GPT 補中間的格子。

### 5.4 算圖與合成

- **引擎：** 正式算圖用 EEVEE（快，適合這種風格）；需要玻璃折射和真實反光的 S15，可以單獨用 Cycles 算。
- **輸出：** `//render/almost_####.png`，1080×1920，1–1440 幀。
- **合成（OpenMontage compose 階段）：** 圖片序列 → 加計時器、文字卡、字幕 → 混音 → H.264，−14 LUFS。計時器建議在合成時疊加（數字比較清楚，也比較好改），Blender 裡的 LED 只在揭曉鏡頭出現。雨也在合成時疊加，只疊在 S01–S14 和 S17b（機台內的鏡頭）。
- **後製光暈：** 在 Compositor 加 Glare（Fog Glow），讓霓虹燈、火光和月亮燈發光。

## 6. 用 OpenMontage 跑這支片

OpenMontage 的規則是**所有製作都要走 pipeline**。這支片最接近的是：

- **`animation` pipeline**，渲染路徑 = Blender 輸出圖片序列 → FFmpeg / Remotion 合成（參考 `skills/meta/animation-runtime-selector.md` 裡「Blender frames + ffmpeg packaging」那一列）。
- 2D 立牌的角色規格可以參考 `character-animation` pipeline 的 `character_design` 和 `pose_library` 格式。

**對應的階段：**

| OpenMontage 階段 | 這支片的產出 | 狀態 |
|---|---|---|
| research | 參考資料 = 你的故事板 + 角色設定圖 | ✅ 已完成 |
| proposal | 第 1、2 節（概念 + 修改建議） | ✅ 等你確認 |
| script | 第 3 節腳本 | ✅ 等你確認 |
| scene_plan | `openmontage/scene_plan.json` | ✅ |
| assets | `ASSET_PROMPTS.md` → 你用 GPT 生成 → 放進 `assets/` | ⏳ 你負責 |
| edit | Blender 時間軸（腳本已經排好）→ 算圖 | ⏳ 素材到位後 |
| compose | 計時器 / 文字 / 音效 / 音樂 → H.264 | ⏳ |
| publish | 標題、說明、標籤（第 7 節） | 草稿 |

在 OpenMontage 裡可以這樣開始：

```text
用 animation pipeline 做一支 60 秒 9:16 Shorts，
腳本與分鏡在 almost-short/README.md，scene plan 在 almost-short/openmontage/scene_plan.json，
畫面由 Blender 算出 almost-short/render/ 的 PNG 序列，請負責 compose：
疊上倒數計時器與三張文字卡、配樂與音效、輸出 YouTube Shorts 規格。
```

> ⚠️ 依照 OpenMontage 的規則，compose 前它會問你要用 **Remotion 還是 HyperFrames**。這支片的畫面已經在 Blender 算好，合成只是疊字和混音，我建議用 **Remotion**（計時器和字卡用 React 寫很直覺）；HyperFrames 比較適合要跟著音樂節拍剪的片。

## 7. 上架資訊草稿

- **標題：** `她只差一點就得救了… #shorts`（備選：`最後一個倖存者，等到了巨爪`）
- **說明：** `你也玩過這台嗎？ 🕹️ #夾娃娃 #喪屍 #動畫 #shorts #反轉`
- **觀眾設定：** **不是為兒童打造**（有恐怖驚嚇元素）。沒有血腥，通常不需要自己加年齡限制。
- **廣告收益：** 沒有血腥比較有機會拿到完整廣告；壓制畫面維持只有抓、拉、壓。
- **封面不要用壓制畫面**，縮圖的審查比影片本身更嚴格。
- **封面：** 用 S09 Rin 笑著被夾到「月亮」前的畫面（騙點擊的希望感），**不要**用揭曉畫面。
- **AI 標示：** YouTube 要求寫實的 AI 生成內容要勾選「經過變造或合成的內容」；這支是明顯的動畫風格，通常不需要，但如果角色畫得很寫實，建議勾選。

## 8. 製作順序建議

1. 先確認第 2 節的修改和第 3 節的腳本。
2. **先生成最優先的 5 組逐幀組圖**（`ASSET_PROMPTS.md` 標 ★ 的）→ 放進資料夾 → 重跑腳本 → 看動作節奏和風格是否融合。
3. 確認風格後再補齊剩下的姿勢圖和背景。
4. Blender 微調鏡頭和燈光 → 算全片。
5. 交給 OpenMontage compose → 輸出 → 上架。
